State Event Plotting Standardization Plan
=========================================

Purpose
-------
This document captures the current state-event overlay behavior from
``pyologger/notebooks/A_interactive_deployment_overlay_manual.ipynb`` as a
migration contract before porting and standardizing across the repo.

Notebook Source Snapshot (Current Truth)
----------------------------------------
Source cells:

- Cell 3: cluster event materialization + baseline ``state_annotations`` creation
- Cell 4: style expansion and normalization into final per-key configs
- Cell 5: ``plot_tag_data_interactive(...)`` invocation

Current runtime defaults in the notebook:

- ``render_state_on_signal_rows = True``
- ``show_dedicated_state_subplot = False``
- ``state_channel_mode = None`` (because dedicated subplot is disabled)
- ``signal_draw_line = False``
- ``signal_shade_mode = "fill_trace_split"``
- ``enable_start_markers = False``
- ``split_gap_low_pct = 45.0``
- ``split_gap_high_pct = 55.0``

Cluster event preprocessing invariants:

- Cluster windows are converted to events with:
  - ``datetime = window_start``
  - ``duration = (window_end - window_start).total_seconds()``
  - ``value = cluster_rank``
  - ``key = cluster key string``
- Cluster events are sorted by ``datetime`` before merge.
- Merged ``event_data`` is sorted by ``datetime`` after merge.
- Existing events with matching cluster keys are replaced.

State Annotation Contract (As Used by Notebook)
------------------------------------------------
Each state key is normalized to one-or-more config dicts with these important
fields:

- Identity/style:
  - ``signal``
  - ``color``
  - ``legend_key`` (optional)

Targeting semantics:

- ``signal: "all"`` expands to all visible signal rows in plotting order.
- ``signal: "__all__"`` and ``signal: "*"`` are treated the same as ``"all"``.
- When ``signal`` is omitted, ``__event_targets__`` from the color-mapping JSON
  is used.
- Multi-target JSON entries expand one state config into multiple per-signal
  overlays.
- When neither explicit ``signal`` nor JSON targets resolve, fallback chooses a
  sensible primary signal (for example ``depth`` for dive-like events).
- Signal-row rendering:
  - ``draw_line``
  - ``line_width``
  - ``line_opacity``
  - ``shade_mode`` in ``{"", "all_y", "fill_trace", "fill_trace_above", "fill_trace_split"}``
  - ``shade_opacity``
- Segmentation:
  - ``default_duration_s``
  - ``merge_gap_seconds``
  - ``line_bridge_seconds``
- Start marker (optional):
  - ``start_marker``, ``start_marker_symbol``, ``start_marker_size``, ``start_marker_opacity``
- Dedicated state-channel row (optional):
  - ``state_channel``
  - ``state_channel_draw_mode`` in ``{"line", "fill_trace", "fill_trace_split"}``
  - ``state_channel_draw_line``
  - ``state_channel_fill_opacity``
  - ``state_channel_fill_half_height``
  - ``split_gap_low_pct`` / ``split_gap_high_pct``

Behavioral Expectations to Preserve
-----------------------------------
- Fill split mode should render two opaque bands with a center gap.
- Per-signal overlays should be generated by expanding each cluster key across
  all visible signals (when ``render_state_on_signal_rows=True``).
- Dedicated subplot mode should be optional and independently configurable.
- Cluster cadence fallback should default to 10 s when duration inference fails.
- Per-signal line width scaling should use robust span quantiles
  (2nd/98th percentile in notebook defaults).

Known Gaps to Resolve During Port
---------------------------------
- Fill hover currently does not trigger on shaded polygons in current plotter
  implementation because fill traces are emitted with ``hoverinfo="skip"``.
- Plotly-resampler zoom update can fail when relayout payload includes
  ``xaxis*.range`` arrays instead of explicit ``range[0]/range[1]`` keys.
  Current error observed: ``ValueError: too many values to unpack (expected 2)``.

Port and Standardization Checklist
----------------------------------
Phase 1: Notebook cleanup and freeze

1. Remove notebook-only scaffolding from state config cells; keep only intended
   defaults and mode toggles.
2. Record one canonical default preset for:
   - overlay-on-signal rows
   - dedicated state subplot mode
3. Confirm all state events are sorted by ``datetime`` before plotting.

Phase 2: Single shared implementation in ``plotter.py``

1. Extract state config normalization into one helper path (input -> normalized
   list of per-key configs).
2. Keep exactly one state rendering pipeline for:
   - signal-row overlays
   - optional dedicated state rows
3. Remove duplicated/parallel state rendering branches so all call paths share
   the same logic.

Phase 3: Cross-repo API standardization

1. Define one stable call surface around ``plot_tag_data_interactive`` for
   state-event options.
2. Update callers to that surface:
   - notebook manual overlay flow
   - ``DiveDB/dash/graph_utils.py``
   - ``pyologger/dash/graph_utils.py`` (if still active)
   - ``pyologger/dash/integrated/integrated_dash.py`` integrations
3. Align names/defaults for modes and percentages across callers.

Phase 4: Interaction + reliability hardening

1. Add explicit policy for fill hover behavior (enabled/disabled) and implement
   consistently.
2. Add relayout sanitization before ``construct_update_data_patch`` calls:
   - keep active x-axes only
   - expand ``xaxis*.range`` list payloads to explicit bounds
   - mirror primary range across active x-axes for shared-subplot figures

Phase 5: Regression tests

1. Unit tests for state segment construction and split fill bounds.
2. Unit tests for state annotation normalization (single dict vs list input).
3. Integration test for plotly-resampler relayout payload handling.
4. Smoke tests for these mode combinations:
   - line only
   - fill only
   - fill split
   - dedicated state row on/off

Acceptance Criteria
-------------------
- Notebook and Dash entry points produce equivalent state overlays from the same
  ``state_annotations`` input.
- No relayout/unpack exceptions during zoom/pan in FigureResampler callbacks.
- Chosen hover policy for filled overlays is implemented consistently across all
  state rendering modes.
